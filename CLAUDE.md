Cargo workspace: `seq-decode` (the shared, backend-neutral Live decoders), `seq-bridge` (C ABI surface the daemon consumes), and per-backend wire-format crates — `seq-structs-live` / `seq-structs-test` are struct mirrors (Rust mirrors of `../showeq-daemon/src/backend/<t>/everquest.h`, generated by `tools/gen_eqstructs.py`); `seq-backend-eql` is the FULLY SELF-CONTAINED eql decode stack — it vendors its own copies of every parser + output struct + a PINNED `eqstructs` module (`src/bindings.rs` + `src/eqstructs.rs`, a frozen fork of the live struct layouts), so eql depends on NOTHING from `seq-decode`/Live (a Live wire patch cannot reach eql — clean-break refactor 2026-07-09). **Backend-specific wire code lives in its own per-backend crate (`seq-structs-{live,test}` struct mirrors feeding the shared `seq-decode` for live/test; `seq-backend-eql` self-contained for eql), never crossed.**
Backend selection is via Cargo features on `seq-bridge`: `backend-live` (default), `backend-test`, `backend-eql` — **all three are real**. The FFI surface is uniform (`seq::rust::decode_*` names are identical for every backend); the linked feature decides each function's implementation. `backend-live`/`backend-test` forward to `seq-decode`, which `#[cfg]`-selects its bindings crate (`crate::eqstructs` = `seq-structs-live` vs `seq-structs-test`). `backend-eql` links ONLY `seq-backend-eql` — **no `seq-decode` edge** (verify: `cargo tree -p seq-bridge --no-default-features --features backend-eql`). The bridge's `backend` alias (`use seq_decode as backend` for live/test, `use seq_backend_eql as backend` for eql) points every `decode_*` at the active stack; the opcodes whose Legends wire diverges are served by eql's OWN same-named parsers through that alias (`parse_player_self_pos` / `parse_spawn` / `parse_consider` / `parse_new_zone` / `parse_player_profile` / `parse_player_spawn_pos` — every eql parser now shares its Live counterpart's canonical name, only the impl differs; the old `parse_legends_*` / `parse_zone_spawn` names were dropped, do not reintroduce them); eql-only functions with no Live twin (e.g. `parse_stat_sync`, `size_overrides`) are called explicitly via `seq_backend_eql::` under `#[cfg(feature = "backend-eql")]`. seq-backend-eql vendors pinned copies of the ~40 shared parsers too (identical to Live *today* — byte-verified by the eql tier-2 goldens); when eql and Live diverge, only eql's copy changes. Rationale: eql is a separate server, and riding Live's decoders meant a Live-only patch could silently corrupt eql. The daemon links exactly one backend per `-DSEQ_TARGET` (Corrosion `NO_DEFAULT_FEATURES` + one `backend-*`).
Build: `cargo build --workspace`; tests: `cargo test --workspace`. The integration check is daemon-side — rebuild the daemon (`cmake -B build` — Rust is unconditional, no `SEQ_USE_RUST` toggle) then run `tests/replay/check.sh` against tier-2 fixtures.
42 opcodes are routed through Rust as of Stage A+10: OP_MobUpdate, OP_DeleteSpawn, OP_ZoneEntry, OP_RemoveSpawn, OP_HPUpdate, OP_MobHealth, OP_SpawnAppearance, OP_ExpUpdate, OP_LevelUpdate, OP_SkillUpdate, OP_ManaChange, OP_Stamina, OP_EndUpdate, OP_Consider, OP_SpawnRename, OP_TargetMouse, OP_Death, OP_ClickObject, OP_Illusion, OP_Buff, OP_Action2, OP_WearChange, OP_ZoneChange, OP_DzInfo, OP_DzSwitchInfo, OP_CastSpell, OP_Action (two-variant), OP_GroupDisband, OP_GroupDisband2, OP_GroupFollow, OP_CorpseLocResponse, OP_SpawnDoor (per-element 136b doorStruct, daemon iterates the array), OP_GroundSpawn (variable-length NetStream), OP_ClientUpdate (both 42b + 28b variants via hand-rolled bit-extract), OP_NpcMoveUpdate (variable 13..24b BitStream sign-magnitude), OP_SendZonePoints (per-element 24b zonePointStruct), OP_SimpleMessage / OP_FormattedMessage / OP_SpecialMesg (message opcodes), OP_CommonMessage (channel chat — NetStream-style), OP_NewZone (NetStream variable-length), OP_PlayerProfile (long NetStream walk; daemon-consumed fields exposed only). Toggle/fallback removed in Phase 1. All remaining C++ decode paths closed 2026-07: `decode_buff` (rewritten for the variable-size OP_Buff — 13b fade / 30b initial / 34+b update), `decode_group_member_list` (roster name-scan), and `SpawnShell::shroudSpawn` (reuses `decode_spawn`); the C++ `fillSpawnStruct` spawn parser is deleted — **Rust is literally the only decoder**. New opcodes: add the parser in `seq-decode`, expose via `seq-bridge`'s cxx surface, replace the daemon's NetStream/struct-cast handler with a `seq::rust::decode_X` call.
`seq-structs-{live,test}/src/bindings.rs` are generated and committed — regenerate after any everquest.h struct change with `python3 tools/gen_eqstructs.py all` (or `live`/`test` for one; defaults to `live` from the sibling daemon checkout). **eql's bindings live at `seq-backend-eql/src/bindings.rs` and are a PINNED fork: `all` never regenerates them.** Regenerate on demand from an explicit (fork) header — `python3 tools/gen_eqstructs.py eql <path/to/everquest.h>` — so eql pulls upstream struct changes on its own terms, never automatically from Live. The script's `ALLOWLIST` mirrors the prior bindgen `.allowlist_type()` set; layout tests in the generated file guard sizes. Trailing `/*offset*/` markers in everquest.h can be stale (e.g. `spawnIllusionStruct` marks 336 but actual size is 332) — the script trusts the per-field declarations and warns on disagreement. No libclang / bindgen dep. **Exception: `spawnPositionUpdate` is hardcoded** — its bitfield pack cannot be parsed generically, so `parse_spawn_position_update()` and the `impl spawnPositionUpdate` accessor block in `emit_rust()` must be updated manually if that struct's layout changes in everquest.h.
`gen_eqstructs.py` can't parse multi-field bitfield groups (e.g. `pitch:12, y:19, padding:1` on one offset line) — it raises ValueError. For bitfield-laden structs hand-roll the parser in `seq-decode` directly on `&[u8]` without a `seq-structs` binding (see `player_self_pos.rs`, `player_spawn_pos.rs`); `spawnPositionUpdate` is the lone codegen special-case. Stale `/*OFFSET*/` comments on commented-out C lines are still parsed and trip the size cross-check — fix `everquest.h` rather than work around.
Deriving a new eql (or post-patch) parser: if per-axis scale factors look arbitrary (÷8 / ÷64 / unscaled) or a value wraps at a power of two, you are reading truncated windows of a packed bitfield — check against Live's packed layouts (19-bit ×8 coords in `spawnPositionUpdate` / spawnStruct position words) before inventing byte offsets. Decisive cheap test: sign-fill — the bits above a signed bitfield must equal its sign bit across every captured packet; float/int32 scans cannot see byte-straddling bitfields, so they prove nothing about their absence. eql default: try the shared Live decoder FIRST — OP_NpcMoveUpdate, OP_MobUpdate, OP_TargetMouse, and OP_EnterWorld all proved byte-identical to Live; an offset parser in `seq-backend-eql` is the fallback, not the starting point. **Position parsers name their fields in the MAP frame — always, every backend.** Upstream's legends branch names EQL position bitfields in the WIRE frame and transposes x/y at the call site (`spawnPositionUpdateEQL` + `SpawnShell::updateSpawns`), so porting its struct labels without that swap silently transposes the axes — how OP_MobUpdate broke between 07/28 and 08/03. Read its consumer, not just `everquest.h`, and convert to the map frame inside the parser; the `decode_*` FFI contract is uniform across backends and must not shift meaning per target.
Gotcha: eql's spawn/ZoneEntry parser is `parse_spawn` in `lib.rs` (returns `ZoneSpawn`). It shares the canonical Live name (uniform surface — the whole crate is named to match its `seq-decode` twins) but is a DIFFERENT impl reading eql's wire, so `seq-backend-eql` must contain exactly ONE `parse_spawn` — its own. The crate once carried a SECOND, vendored Live-copy `parse_spawn` (spawn.rs); running that Live-format parser on an eql record silently returned garbage (`ok=true`, race ≈ 2.2e9, class 0, no error), so it was DELETED (2026-07-11). **WARNING: never re-vendor a Live-copy spawn parser (or any Live-copy of an eql-diverged opcode) into seq-backend-eql** — eql's `parse_spawn` must stay eql's own; a stray duplicate would compile but silently mis-decode. General rule: before reusing any `parse_*`/`decode_*` in eql code, reuse the exact one the eql `decode_*` bridge impl (`#[cfg(feature="backend-eql")]`) calls — under `backend-eql` the `backend` alias and `seq_backend_eql::parse_spawn` both resolve to eql's parser, so the danger is not a cross-crate mixup (only one backend links) but an accidental second copy inside the eql crate. New eql-only decoders follow the `decode_stat_sync` bridge pattern: real impl under `#[cfg(feature="backend-eql")]` + inert stub under `#[cfg(not(...))]`.
When eql diverges on an opcode that already has a shared `decode_*` FFI, **rewrite eql's OWN parser copy** behind that FFI instead of adding new bridge surface — Live's `seq-decode` copy stays untouched, so live/test are byte-identical (regression-free). E.g. eql's 28B `playerSpawnPosStruct` reuses `decode_player_spawn_pos` via a rewritten `seq-backend-eql::parse_player_spawn_pos`; only `size_overrides()` + the toml flip are added, no new FFI.
eql gate sizes are BACKEND-OWNED: a mapped `SZC_Match` payload with no `size_overrides()` entry silently inherits Live's compiled `sizeof`. Fix by declaring the size from that parser's own `PAYLOAD_LEN` — never by re-pointing the payload at a Live struct name that happens to fit. A wrong gate usually hides a second bug: eql's vendored parser still reading the pinned Live layout.
Never use an `EQL` suffix in a name we own (opcode or struct); cite upstream's `<name>EQLStruct` inside comments only. If upstream's EQL-suffixed name collides with a neutral name we already use, pick a neutral one from upstream's DESCRIPTION of the packet.
Two distinct bitfield conventions live in the wire formats: (a) C-struct `#[repr(C, packed)]` LSB-first within each storage unit (what `spawnPositionUpdate` and the new `playerSelfPosStruct`/`playerSpawnPosStruct` parsers use), and (b) the legacy `BitStream` MSB-first sign-magnitude packing in `netstream.cpp` (used by `OP_NpcMoveUpdate`, ported to `npc_move_update.rs`). They don't share extraction code — pick the right one per opcode.
