Cargo workspace: `seq-decode` (the shared, backend-neutral Live decoders), `seq-bridge` (C ABI surface the daemon consumes), and per-backend wire-format crates — `seq-eqstructs-live` / `seq-eqstructs-test` are struct mirrors (Rust mirrors of `../showeq-daemon/src/backend/<t>/everquest.h`, generated by `tools/gen_eqstructs.py`); `seq-eqstructs-eql` holds eql's offset parsers (eql owns no C wire structs). **Backend-specific wire code lives in its own `seq-eqstructs-*` crate, never in the shared `seq-decode`.**
Backend selection is via Cargo features on `seq-bridge`: `backend-live` (default), `backend-test`, `backend-eql` — **all three are real**. The FFI surface is uniform (`seq::rust::decode_*` names are identical for every backend); the linked feature decides each function's implementation. `backend-live`/`backend-test` forward to `seq-decode`, which `#[cfg]`-selects its bindings crate (`crate::eqstructs` = `seq-eqstructs-live` vs `seq-eqstructs-test`). `backend-eql` reuses the Live decoders (`seq-decode`+`backend-live`, since eql's wire matches Live for ~38 opcodes) and pulls in `seq-eqstructs-eql` for the 5 diverged opcodes (spawn, profile, self-pos, new-zone, mob-update — offset parsers ported from the daemon's `EqlDispatch`, producing the shared `seq-decode` output structs so the bridge maps them identically). The daemon links exactly one backend per `-DSEQ_TARGET` (Corrosion `NO_DEFAULT_FEATURES` + one `backend-*`).
Build: `cargo build --workspace`; tests: `cargo test --workspace`. The integration check is daemon-side — rebuild the daemon (`cmake -B build` — Rust is unconditional, no `SEQ_USE_RUST` toggle) then run `tests/replay/check.sh` against tier-2 fixtures.
42 opcodes are routed through Rust as of Stage A+10: OP_MobUpdate, OP_DeleteSpawn, OP_ZoneEntry, OP_RemoveSpawn, OP_HPUpdate, OP_MobHealth, OP_SpawnAppearance, OP_ExpUpdate, OP_LevelUpdate, OP_SkillUpdate, OP_ManaChange, OP_Stamina, OP_EndUpdate, OP_Consider, OP_SpawnRename, OP_TargetMouse, OP_Death, OP_ClickObject, OP_Illusion, OP_Buff, OP_Action2, OP_WearChange, OP_ZoneChange, OP_DzInfo, OP_DzSwitchInfo, OP_CastSpell, OP_Action (two-variant), OP_GroupDisband, OP_GroupDisband2, OP_GroupFollow, OP_CorpseLocResponse, OP_SpawnDoor (per-element 136b doorStruct, daemon iterates the array), OP_GroundSpawn (variable-length NetStream), OP_ClientUpdate (both 42b + 28b variants via hand-rolled bit-extract), OP_NpcMoveUpdate (variable 13..24b BitStream sign-magnitude), OP_SendZonePoints (per-element 24b zonePointStruct), OP_SimpleMessage / OP_FormattedMessage / OP_SpecialMesg (message opcodes), OP_CommonMessage (channel chat — NetStream-style), OP_NewZone (NetStream variable-length), OP_PlayerProfile (long NetStream walk; daemon-consumed fields exposed only). Toggle/fallback removed in Phase 1 — Rust is the only decoder. New opcodes: add the parser in `seq-decode`, expose via `seq-bridge`'s cxx surface, replace the daemon's NetStream/struct-cast handler with a `seq::rust::decode_X` call.
`seq-eqstructs-{live,test}/src/bindings.rs` are generated and committed — regenerate after any everquest.h struct change with `python3 tools/gen_eqstructs.py all` (or `live`/`test` for one; defaults to `live` from the sibling daemon checkout). The script's `ALLOWLIST` mirrors the prior bindgen `.allowlist_type()` set; layout tests in the generated file guard sizes. Trailing `/*offset*/` markers in everquest.h can be stale (e.g. `spawnIllusionStruct` marks 336 but actual size is 332) — the script trusts the per-field declarations and warns on disagreement. No libclang / bindgen dep. **Exception: `spawnPositionUpdate` is hardcoded** — its bitfield pack cannot be parsed generically, so `parse_spawn_position_update()` and the `impl spawnPositionUpdate` accessor block in `emit_rust()` must be updated manually if that struct's layout changes in everquest.h.
`gen_eqstructs.py` can't parse multi-field bitfield groups (e.g. `pitch:12, y:19, padding:1` on one offset line) — it raises ValueError. For bitfield-laden structs hand-roll the parser in `seq-decode` directly on `&[u8]` without a `seq-eqstructs` binding (see `player_self_pos.rs`, `player_spawn_pos.rs`); `spawnPositionUpdate` is the lone codegen special-case. Stale `/*OFFSET*/` comments on commented-out C lines are still parsed and trip the size cross-check — fix `everquest.h` rather than work around.
Two distinct bitfield conventions live in the wire formats: (a) C-struct `#[repr(C, packed)]` LSB-first within each storage unit (what `spawnPositionUpdate` and the new `playerSelfPosStruct`/`playerSpawnPosStruct` parsers use), and (b) the legacy `BitStream` MSB-first sign-magnitude packing in `netstream.cpp` (used by `OP_NpcMoveUpdate`, ported to `npc_move_update.rs`). They don't share extraction code — pick the right one per opcode.
