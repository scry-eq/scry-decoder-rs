Cargo workspace with 3 members: `seq-decode` (parsers), `seq-bridge` (C ABI surface the daemon consumes), `seq-eqstructs` (Rust mirrors of `../showeq-daemon/src/everquest.h`).
Build: `cargo build --workspace`; tests: `cargo test --workspace`. The integration check is daemon-side — rebuild the daemon with `cmake -DSEQ_USE_RUST=ON -B build` then run `tests/replay/check.sh`; it does a second cmp pass with the Rust decoder enabled and the cross-decoder bytes must match the C++ goldens.
Stage A scope: only `OP_MobUpdate` is routed through Rust today (daemon flag `--rust-opcodes OP_MobUpdate`). New stages = adding opcode names to that comma-separated list and the corresponding parsers in `seq-decode`.
`seq-eqstructs/src/bindings.rs` is generated and committed — regenerate after any everquest.h struct change with `python3 tools/gen_eqstructs.py [path/to/everquest.h]` (defaults to the sibling daemon checkout). The script's `ALLOWLIST` mirrors the prior bindgen `.allowlist_type()` set; layout tests in the generated file guard sizes. Trailing `/*offset*/` markers in everquest.h can be stale (e.g. `spawnIllusionStruct` marks 336 but actual size is 332) — the script trusts the per-field declarations and warns on disagreement. No libclang / bindgen dep.
